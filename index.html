배경
채널마다 정산서 양식과 공제 항목이 달라 매월 채널별 대사 파일을 새로 만들었고, 정산서는 사람이 파트너 사이트 수십 곳에 로그인해 내려받았습니다. 열 위치가 달마다 밀려 수식이 조용히 틀어지는 일이 반복됐습니다.
한 일
정산서를 하나의 대사 양식으로 표준화하고 ERP 실판매 기준으로 상품매출·수수료·반품을 건별 자동 매칭했습니다. 반복되는 차이는 원인을 지정해 상시 차이로 분리했고(차수별 분할지급, 기준 미달 미지급, 프로모션 공제, 세트·색상묶음 품번), 열은 위치가 아니라 헤더 이름으로 읽게 바꿨습니다. 정산 API가 있는 채널은 API로, 없는 채널은 자격증명을 암호화 금고에 두고 브라우저를 자동 조작하는 무인 수집기로 매월 자동 수집합니다(2단계 인증 자동 생성 포함).
결과
34채널 전수를 원 단위까지 재현하는지 확인했고, 남은 차이 3건은 전부 원인을 규명했습니다. 채널별 차이는 채널×원인 축의 화면으로 상시 조회되고, 전월 이력과 비교됩니다. 정산서 수집은 11채널이 무인으로 돌아갑니다.

01차이는 덮지 않고 분류한다

원인이 지정된 차이는 다음 달에 다시 조사하지 않습니다. 마감이 매달 새로 하는 조사에서, 기준에 맞춰 확인하는 작업으로 바뀝니다.

02검증 없이 편해지지 않는다

자동으로 나온 숫자는 원천 합계와 대사하고, 재계산해도 같은 값인지 확인한 뒤 사용합니다. 원 단위까지 재현되지 않으면 확정하지 않습니다.

03판단은 문서로, 반복은 기계로

기준이 필요한 항목은 대안과 채택 근거를 남겨 사람이 판단하고, 반복 확인만 자동화합니다. 그래야 감사·상급자에게 설명이 됩니다.

01기준 레이어

워크스페이스 최상위에 모든 세션이 먼저 읽는 기준 문서를 둡니다. 파일 버전 규칙(_vN, 덮어쓰기 금지), 엑셀 품질 바(수식 오류 0·합계 대사·재계산), 지면 품질 바(대비 4.5:1·강조 면적·표 조판 수치), 환경 함정, 금지 목록, 막혔을 때의 에스컬레이션. "꼼꼼하게" 같은 형용사 대신 체크 가능한 기준만 적습니다.

02스킬 10개

반복되는 작업 절차를 스킬로 고정합니다 — 증거 기반 완료 판정 자율 실행(/goal), 업무 전체 감사·로드맵(/consultant-audit), 해결 직후 추론 박제(/extract-approach), 방법론 교차검증 사이클(/methodology-review), UX 토큰 가이드·수정 사이클(ux-guide·ui-redline), 월 마감 안내 메일, 영수증 일괄 수집, 주문 조회.

03기억 체계

세션이 끝나도 남아야 하는 것은 메모 노트 159개로 축적합니다 — 프로젝트 상태, 데이터 함정(예: 재고 코호트에 매출 DB를 쓰면 안 되는 이유), 받은 피드백(왜·어떻게 적용). 연구 결과는 지식 금고에 1노트 1통찰로 원자화하고, 과거 세션 45개를 전수 스윕해 흩어진 규칙을 회수했습니다.

04모델 간 교차검증

판단이 걸린 숫자는 한 모델의 답을 믿지 않습니다. 검토 대상을 항목 표로 분해해 다른 AI(Codex)를 반박자로 세우고, 합의/부의를 기록한 뒤 사람이 확정합니다. 검토·핸드오프·공통결론 폴더로 두 AI의 산출물을 교환하고, 재고 평가는 이 사이클을 7라운드 돌려 표 간 정의 불일치를 잡았습니다.

05시스템을 직접 만지게

AI가 화면을 보고 조작합니다 — 브라우저 자동 조작 6,300여 회(ERP·파트너 정산 사이트·데이터 저장소), 구글시트·저장소·메일은 커넥터(MCP)로, 정산서 수집은 로그인 자동화로 무인화. 화면 탐색보다 API 직접 호출을 우선하고, 화면 버그는 로컬 시험대에서 실측합니다.

06운영과 거버넌스

사용량은 주간 운영일지로 남깁니다(세션 기록 → DB 적재 → 리포트 이미지, 결제 구분·한도 스냅샷 포함). 계정을 팀 3인 공용으로 전환하며 온보딩 문서 2종(사용 방식·보안 점검, 개발 용어 65개)을 만들었고, 메일 자동 발송·삭제·금전 실행은 금지로 고정했습니다. 완료는 증거가 있을 때만 선언합니다.

자주 받는 질문

회계 담당자가 왜 직접 자동화까지 하나요?

대사 업무는 차이의 원인을 아는 사람이 규칙을 정해야 자동화가 됩니다. 외부에 맡기면 "무엇이 정상 차이인지"를 전달하는 데 더 많은 시간이 들었습니다. 그래서 기준을 정하는 일과 그 기준을 코드로 옮기는 일을 같이 했습니다.

자동화한 숫자를 어떻게 믿습니까?

세 가지를 확인한 뒤에만 씁니다. ① 원천 데이터 합계와 결과물 합계가 원 단위까지 일치하는지 ② 다시 계산해도 같은 값이 나오는지 ③ 이전 확정본을 재현하는지. 하나라도 안 맞으면 원인을 규명할 때까지 확정하지 않습니다.

AI가 만든 결과를 그대로 쓰나요?

아니요. 판단이 필요한 항목은 표로 분해해 근거를 적고, 다른 모델을 검토자로 세워 교차검증한 뒤 사람이 확정합니다. AI는 반복 확인과 초안 작성에 쓰고, 기준 결정은 사람에게 남깁니다. 구체적인 구조는 위 "AI를 쓰는 방식"에, 팀에는 온보딩 문서로 공유했습니다.

이 페이지에 실제 숫자가 없는 이유

재직 중인 회사의 금액·거래처·내부 시스템 정보는 공개하지 않습니다. 성과는 건수·비율·구조로만 적었고, 데모는 전부 생성된 샘플 데이터로 동작합니다. 상세 내용은 면접에서 회사 정보를 침해하지 않는 범위로 설명드리겠습니다.
